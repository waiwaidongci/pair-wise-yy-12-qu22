# 蹄铁安全派工台

蹄铁师上门前只看得到马号，到了马房才发现马不肯抬蹄、会踢人或需要搭档按住。
本工作台把「修蹄记录」改造成「安全派工台」：先登记每匹马的抬蹄习惯、踢人次数和配合评分，再决定单人还是双人时段。

## 安全规则

- **每匹马登记**：马号、抬蹄习惯（愿意抬蹄 / 需引导 / 需搭档按住 / 不肯抬蹄）、累计踢人次数、配合评分历史。
- **高风险马只能排双人时段**：踢过人、需搭档按住或不肯抬蹄自动判为高风险（也可人工指定），排入单人时段会被拦截；双人时段必须填写搭档姓名。
- **同一匹马当天只留一张未完成派工单**：待排或已排都算占用，重复开单被拦截。
- **一次安全修蹄记一次配合**：完成时登记 1–5 分；连续两次达到 4 分，高风险马**自动降为普通**；低于 4 分或发生踢人则连续计数清零，踢人次数 +1（普通马踢人回升为高风险）。
- **原安排失效并重新待排**：改动风险等级、取消派工，或踢人导致风险回升时，该马已排入时段的派工单立即清空时段、退回待排；停用/删除时段同样处理。每张派工单保留完整事件流水。

## 三层结构（记录 / 判断 / 页面分开）

- `src/domain/rules.ts` — 判断层（纯函数）：风险判定、开单/排单校验、配合计分与降级规则，不依赖 React 和存储。
- `src/data/` — 记录层：`store.ts` 负责 localStorage 读写与发布订阅，`seed.ts` 提供默认时段与示例数据。
- `src/domain/actions.ts` — 业务动作层：把判断层规则应用到记录层数据。
- `src/ui/` — 页面层：`BoardPage`（今日派工）、`HorsesPage`（马匹档案）、`SettingsPage`（时段与数据）。
- 数据全部存在浏览器 `localStorage`（键 `farrier-dispatch:v1`），支持导出 / 导入 JSON 备份，不上传任何服务器。
